# 플레이어 이동 구현 방식 기록

## 구현 개요

벤더 캐릭터의 애니메이션 입력을 재사용하면서, 실제 이동과 중력·점프는 `CharacterController` 기반의 `PlayerLocomotion`이 담당한다. 마우스 시점 입력은 별도의 `LookSmoothing`이 처리하고, 몸통 회전은 카메라의 곁눈질 회전이 일정 각도를 넘었을 때 이를 몸통 회전으로 넘기는 방식이다.

## 이동 처리

- `TacticalProceduralAnimation.moveInput`을 이동 입력으로 사용하고 크기를 1로 제한한다.
- 입력 방향은 몸통이 아니라 카메라의 수평 전방·오른쪽 벡터를 기준으로 계산한다. 시점과 몸 방향이 잠시 어긋나도 WASD가 화면 방향과 일치한다.
- 기본 보행 속도는 2.5m/s, 앞으로 이동하며 왼쪽 Shift를 누르면 5.5m/s로 달린다.
- `CharacterController.isGrounded`일 때 Space 입력으로 점프 속도를 만들고, 공중에서는 중력을 누적한 뒤 `CharacterController.Move`로 이동한다.

## 시점과 몸통 회전

- `LookSmoothing.OnLook`은 마우스 델타에 감도를 적용해 누적하고, 프레임률과 무관한 지수 감쇠로 조금씩 시점에 반영한다. 각도 목표값을 보간하지 않고 현재 `pitchInput`/`yawInput`에 더하므로 사격 반동으로 변한 시점을 자동으로 되돌리지 않는다.
- 프리룩 중에는 입력을 별도 자유 시점 입력으로 전달한다.
- `PlayerLocomotion`은 Kinemation이 관리하는 `yawInput`의 절댓값이 기본 곁눈질 범위 45도를 넘으면 초과분만 몸통 회전에 넘기고 같은 양을 `yawInput`에서 뺀다. 카메라의 전체 방향이 유지되어 회전이 튀지 않는다.
- `LeanCameraTilt`은 Kinemation의 부드럽게 변하는 `leanInput`을 카메라 롤로 변환한다. 기본 배율은 몸 기울기 1도당 화면 0.3도이며 최대 화면 기울기는 12도다.

## 입력 잠금과 실행 순서

이동에는 `PlayerLocomotion.InputEnabled`, 시점에는 `LookSmoothing.InputEnabled`가 있다. 모딩 UI나 다른 동작은 이를 통해 플레이어 입력을 막을 수 있다. 시점 입력 처리는 벤더 카메라 갱신보다 먼저, 화면 기울임은 벤더 카메라가 회전을 쓴 뒤 실행되도록 `DefaultExecutionOrder`를 지정했다.

## 범위 및 제약

- 이동 입력·시점 입력의 일부는 KINEMATION Tactical Shooter Pack의 `TacticalProceduralAnimation` 및 `PlayerInput`에 의존한다.
- 이 기록은 코드 구현을 설명하며, 별도 이동 테스트 결과나 현재 씬의 인스펙터 수치는 여기서 재검증하지 않았다.
