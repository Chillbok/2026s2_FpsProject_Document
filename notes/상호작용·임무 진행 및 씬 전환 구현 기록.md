# 상호작용·임무 진행 및 씬 전환 구현 기록

## 구현 개요

월드 상호작용은 `IInteractable` 계약을 구현하는 컴포넌트를 전역 목록에서 찾아 플레이어가 실행하는 방식이다. `PlayerInteractor`는 가까운 대상을 고르고 프롬프트를 갱신하며, 문·아이템·씬 출입구·탈출 차량은 각자의 잠금 조건과 동작을 구현한다. 씬 전환과 런 상태 보존은 정적 `GameProgress`, 씬 초기화는 `SceneFlow`가 맡는다.

## 상호작용 대상 선택과 실행

- 플레이어 시작 시 `PlayerInteractor`가 상호작용 프롬프트를 생성하고 같은 오브젝트에 `DoorCamera`를 추가한다 (`Assets/Scripts/Player/PlayerInteractor.cs:26-32`).
- 기본 상호작용 거리는 2m다. 플레이어 위치에서 위로 1m 올린 기준점과 대상의 `InteractionPoint` 사이를 비교하며, 층간 오선택을 줄이기 위해 높이 차가 1.5m보다 큰 대상은 제외한다. 남은 대상 중 가장 가까운 하나가 선택된다 (`PlayerInteractor.cs:13-15`, `:79-99`).
- F 입력은 Input System `PlayerInput`의 Send Messages를 통해 `OnInteract`로 전달된다. 일시정지·완료 화면·사망 상태에서는 동작하지 않는다. 선택 대상이 있으면 `IInteractable.Interact`를 호출한다 (`PlayerInteractor.cs:101-129`).
- 문 앞에서는 휠 입력을 무기 전환 입력보다 먼저 소비하도록 `TrySelectDoorAction`을 제공한다. 문이 닫혀 있을 때 열기 또는 내시경 중 하나를 고르고, 열린 문은 열기 모드로 초기화한다 (`PlayerInteractor.cs:54-77`). UI 프롬프트는 코드로 생성되고, 선택된 행동은 굵은 글씨와 불투명도로 구분한다 (`Assets/Scripts/UI/InteractionPrompt.cs:45-70`).

## 문과 내시경

- `Door`는 한 개 또는 여러 개 문짝을 힌지 중심으로 회전시킨다. 열 때는 사용자의 문 기준 위치에 따라 문짝이 사용자 반대 방향으로 열리도록 목표 각도를 고른다. 각도는 프레임 시간에 따른 지수 보간으로 적용한다 (`Assets/Scripts/World/Door.cs:15-25`, `:125-169`, `:171-179`).
- 문은 `requiredItem`이 비어 있으면 잠금 없이 열리고, 값이 있으면 사용자의 `PlayerInventory`에 해당 아이템이 있어야 한다. 적은 주석상 잠금과 무관하게 열 수 있도록 설계되어 있다 (`Door.cs:29-35`, `:99-110`, `:125-129`).
- 문짝이 완전히 열린 동안에는 문 메시의 바운즈를 사용한 `NavMeshObstacle`을 켜 NavMesh carve를 적용한다. 경로는 문틀을 지나갈 수 있게 하고 열린 문짝이 튀어나와 있는 영역은 장애물로 처리하려는 구성이다 (`Door.cs:39-41`, `:63-83`, `:154-168`).
- `Door.CameraPose`는 문 반대편의 낮은 위치와 바라볼 방향을 계산한다 (`Door.cs:112-123`). `DoorCamera.Open`은 플레이어 몸을 이동시키지 않고 별도 카메라를 만들며 640x360 RenderTexture에 장면을 렌더링해 UI RawImage로 표시한다 (`Assets/Scripts/Player/DoorCamera.cs:36-93`).
- 내시경 사용 중에는 무기 발사를 중지하고 Interact 외 입력 액션을 비활성화하며 플레이어 이동과 사격 컴포넌트를 끈다. A/D는 문틈을 따라 카메라를 좌우로 움직이고 SphereCast로 이동 경로를 확인한다. 마우스는 제한된 각도로 시점을 바꾼다. F, 문 열림, 사망, 일시정지, 문과의 거리 이탈 시 카메라와 입력 상태를 정리한다 (`DoorCamera.cs:44-54`, `:95-123`, `:125-147`).
- 이 프로토타입의 문 기능은 상호작용 기반 회전과 정찰 카메라다. 문 발차기는 현재 커밋의 `Door`·`PlayerInteractor` 코드에서 확인되지 않는다.

## 아이템과 임무 상태

- `PickupItem`은 열쇠카드 또는 폴더 형태의 단순 시각 오브젝트를 런타임 생성한다. URP Lit 재질의 발광과 그림자 없는 Point Light로 어두운 장소에서 식별을 돕는다 (`Assets/Scripts/World/PickupItem.cs:12-26`, `:59-88`).
- 줍기는 플레이어의 `PlayerInventory.Add(itemId)`를 호출하고, 설정된 소음이 있으면 `Noise.Emit`을 호출한 뒤 오브젝트를 비활성화한다. 이미 `GameProgress.Items`에 아이템 ID가 있으면 시작 시 다시 표시하지 않는다 (`PickupItem.cs:31-57`).
- `PlayerInventory`는 아이템 ID를 `GameProgress.Items` 집합에 보관하고 새 아이템이 추가될 때 `ItemAdded` 이벤트를 보낸다 (`Assets/Scripts/Player/PlayerInventory.cs:7-19`).
- `Mission`은 순서가 있는 `Step[]`에서 아직 갖지 않은 첫 아이템을 찾고 그 목표 문구를 HUD에 표시한다. 단계의 아이템을 모두 획득하면 탈출 목표를 표시한다 (`Assets/Scripts/World/Mission.cs:13-25`, `:41-58`).
- 임무 완료 시 플레이어 입력을 비활성화하고 완료 화면을 호출한다. 탈출 지점에서 `evidence`를 요구하는 연결은 `MissionGoal`이 수행한다 (`Mission.cs:60-72`, `Assets/Scripts/World/MissionGoal.cs:7-31`).

## 씬 이동, 스폰, 재시작

- `SceneExit`은 대상 씬과 스폰 ID, 표시 문구, 필요 아이템 및 특정 아이템 획득 후 닫힐 조건을 가진다. 사용 가능 상태에서 플레이어가 설정 거리 안에 오면 대상 씬을 비동기로 미리 로드하고, F 상호작용 시 `GameProgress.TravelTo`를 호출한다 (`Assets/Scripts/World/SceneExit.cs:9-21`, `:35-60`).
- `GameProgress`는 런 동안 획득 아이템, 사망한 적 ID와 한 번 선택한 랜덤 선택지를 정적 컬렉션으로 관리한다. 씬 이동 전에 현재 아이템·사망 적을 체크포인트로 복사한다. 사망 후에는 체크포인트 상태를 복구하고 현재 씬을 다시 로드한다 (`Assets/Scripts/World/GameProgress.cs:14-30`, `:70-85`, `:104-116`, `:145-151`).
- 씬 비동기 사전 로딩은 낮은 백그라운드 우선순위로 시작한다. 목적지가 다르면 기존 preload를 활성화한 뒤 목적 씬으로 다시 이동한다. 씬 이동 중에는 `ScreenFade.Cover`로 검은 화면을 만들며, `SceneFlow`가 새 씬 로드 후 페이드와 사운드 프리로드를 마무리한다 (`GameProgress.cs:53-68`, `:118-143`, `Assets/Scripts/World/SceneFlow.cs:38-45`).
- `SceneFlow`는 씬의 `SpawnPoint` 중 `PendingSpawn` ID와 일치하는 점을 선택하고, 일치하는 점이 없으면 기본 스폰을 사용한다. CharacterController를 잠시 끄고 위치·회전을 설정한 뒤 다시 켠다. 이전 방문에서 죽은 적은 씬 시작 시 비활성화 후 제거하고, 살아 있는 적의 사망 이벤트를 런 상태에 기록한다 (`SceneFlow.cs:17-35`, `:47-64`).
- 런 시작은 아이템·적 처치·선택 상태를 초기화하고 `Bridge_Village`로 이동한다. 타이틀 복귀도 런 상태를 초기화한다 (`GameProgress.cs:44-51`, `:87-102`).

## 실제 캠페인 연결

마을 출입구는 병원 `MainDoor` 스폰을 지정하고, `evidence` 획득 후에는 다시 병원으로 들어갈 출입구를 닫는다. 병원 출구는 `evidence`를 얻기 전에는 사용할 수 없으며, 야외 `HospitalGate` 스폰으로 돌아간다. 마을 차량의 `MissionGoal`도 같은 증거 아이템을 요구한다 (`Assets/Scripts/Editor/VillageLevelBuilder.cs:78-110`, `Assets/Scripts/Editor/AsylumEnemyPlacer.cs:238-287`).

씬 상태는 정적 메모리 상태와 현재 프로세스 안의 씬 이동을 대상으로 한다. 저장 파일이나 게임을 종료한 뒤 재개하는 세이브 시스템은 이 코드에서 확인되지 않는다.
