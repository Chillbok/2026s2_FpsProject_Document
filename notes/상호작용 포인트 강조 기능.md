# 개요

> 이 오브젝트는 플레이어가 상호작용할 수 있는 오브젝트라는 것을 알려주기 위한 기능

> [!warning]
> 이 기획은 [[상호작용]] 기능의 프로토타입이 개발된 이후에 필요하다고 생각난 아이디어를 구현하기 위해 추가하였다. 따라서 하단의 내용도 [[상호작용]] 시스템 프로토타입이 구현되었다는 가정 하에 작성한다.

[[상호작용 포인트]]는 플레이어가 특정 무언가와 상호작용할 수 있게 하기 위해 존재한다. 플레이어가 당장 [[상호작용]]할 수 없더라도, 일정 거리 내에 있다면 플레이어에게 '이 물체는 [[상호작용]]할 수 있는 오브젝트입니다' 하고 알려줄 수 있는 요소가 필요하다. 특히 처음 플레이하는 입장에서 이 요소는 생각보다 큰 비중을 차지할 것이라고 판단했다.

예를 들어, [[아크 레이더스]]라는 게임을 예시로 들어보자. 사실적인 그래픽이기 때문에 [[상호작용 ]]가능한 에셋인지 아닌지 구분하기 어려운 그래픽 스타일이기도 하고, 맵 오브젝트와의 [[상호작용]]이 핵심 시스템인 장르의 게임이기 때문에 언급하였다.

![[Pasted image 20261014190917.png]]

저 상자에 저런 아이콘이 없었다면, 익숙하지 않은 플레이어 입장에서 저게 상호작용 가능한 아이템 상자라는 것을 알 수 있을까? 아니다. 즉, 처음 플레이하는 플레이어에게 이게 상호작용이 가능하다는 오브젝트라는 것을 알리기 위해 필요하다.

정보 제공이 목적이기 때문에, 당연히 실제 상호작용 가능 거리보다는 더 길게 표시해야 한다.

## 전제: 현재 감지는 콜라이더가 아니라 쿼리다

> [!warning]
> [[상호작용 반경]] 원안은 "플레이어 안에 고정 크기 트리거 구형 콜라이더를 배치"하는 방식이었지만, 프로토타입은 이를 채택하지 않았다. 현재 감지는 트리거 이벤트가 아니라 `Physics.OverlapSphereNonAlloc(플레이어 몸통 중심, interactRange, ...)` **쿼리**를 매 프레임 수행한다.

즉, "감지 범위"를 정하는 것은 코드의 `interactRange`(=1m) 값이다. 따라서 우리는 이 앞에 조건 하나를 더할 것이다.

- [[상호작용 포인트]]를 표시하는 거리값을 하나 추가하고, 그 거리 이내에 있다면 [[상호작용 포인트 강조 기능]]을 작동한다. 이 거리값은 항상 [[상호작용 반경]]보다 커야 한다.
- 그 거리값 밖으로 벗어나면 다시 [[상호작용 포인트 강조 기능]]을 위한 별도의 UI 에셋을 끈다. 즉, [[상호작용 UI 아이디어|상호작용 UI]]가 표시되더라도 [[상호작용 포인트 강조 기능]]은 항상 작동되는 상태여야 한다.

## 구현 방식 (확정안): 단일 쿼리 + 거리 밴드 2개

탐색용·강조용 콜라이더를 2개 두는 대신, **기존 쿼리 반경을 강조 거리까지 키우고, 계산된 거리로 상호작용/강조를 분류**한다.

- `interactRange`(기존, 1m) 옆에 `highlightRange`(강조 거리, 예: 3~5m)를 추가한다. `highlightRange > interactRange`를 보장한다.
- 매 프레임 쿼리 반경을 `highlightRange`로 두고 후보를 모은다(밀집 지역 대비 재사용 버퍼 크기 확인).
- 각 후보의 거리 $d$로 분류한다:
	- $d \le interactRange$ 이고 [[상호작용 조건]]을 만족 → **상호작용 대상**. 기존 선택 규칙(각도 최소)을 그대로 유지한다.
	- $interactRange < d \le highlightRange$ → **강조 대상**. 상호작용 대상으로 승격되지 않으며 입력을 받지 않는다.
- 강조 대상이 있으면 강조 표시를 켜고, 없으면 끈다. 화면 좌표 투영(`camera.WorldToScreenPoint`)과 배치는 기존 [[상호작용 UI 아이디어|상호작용 UI]]와 동일한 경로(`LateUpdate`)를 쓴다.

### 이 방식을 택한 이유

- 현재 감지가 쿼리 기반이라 콜라이더를 2개 두어도 같은 쿼리에 함께 반환된다. 구분하려면 레이어를 나눠야 해 이득이 없다.
- 거리 $d$는 이미 계산되고 있어 밴드 분류가 사실상 무비용이다. 쿼리 1회·alloc 0을 유지한다.
- 씬/프리팹에 콜라이더를 추가할 필요가 없다.

### 아직 정해야 할 것

- **강조 표시의 정체**: (a) 기존 [[상호작용 UI 아이디어|상호작용 UI]]를 더 먼 거리에서 그대로 표시할지, (b) 키·문구 없는 별도 아이콘([[아크 레이더스]]식)을 표시할지.
- 강조에도 카메라 각도 조건을 둘지(둔다면 상호작용과 동일한 30도인지 별도인지).
- 강조 대상이 여러 개일 때 하나만 표시할지 전부 표시할지.
